## Objective

Remove assistant text-to-speech completely while preserving optional speech-to-text as an editable input path.

The intended lifecycle is:

`idle -> requesting-permission -> listening -> transcribing -> idle/error`

A transcription becomes editable text. It does not submit itself. Atlas responses remain visual text and never reopen the microphone automatically.

### STT input preserved — PASS

- existing `MediaRecorder` / `getUserMedia` capture remains in `src/voice/capture.ts`;
- microphone visualizer/amplitude path remains;
- existing bounded `/api/transcribe` client/Worker path is preserved;
- ordinary transcript result is copied into the answer editor;
- player may edit before explicitly submitting;
- typing remains the complete fallback.

### No automatic submission or microphone loop — PASS

Real-browser coverage proves:

- one dictation capture produces one transcript and zero `/api/turn` calls until explicit submit;
- the transcript can be edited before submit;
- after Atlas returns text, the microphone does not reopen;
- a blank/no-speech result does not fabricate a turn.

### Agency command firewall — PASS

- local command parser remains unchanged;
- real-browser STT test proves spoken STOP executes locally with zero provider turns;
- retained unit coverage protects PASS / PRIVATE / STOP / SERIOUS / HELP / sass parsing and conversational false-positive avoidance;
- typed-vs-transcribed equivalence coverage protects deterministic progression authority.

### Background/cancellation lifecycle — PASS

A reviewer-added real-browser regression test backgrounds the page during active capture and proves:

- capture is cancelled;
- zero transcription calls are made;
- zero provider turns are made;
- microphone UI is no longer active.

Existing concurrency coverage also proves that leaving voice mode while transcription is pending cannot commit the late result.
