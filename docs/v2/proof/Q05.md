## Method
Each slice transition is applied (a) twice from the same base (must be deterministic) and (b) to its own output (must reject or be idempotent). Invariants after every step: unique ids across gaps/seeds/runs/actions/observations/reflections/evidence/memories, at most one active run, activeCombat bound to an active run, at most one Evidence per Reflection. Property loop: 40 run ids across all territories (varying the deterministic encounter pick), each full playthrough replayed twice to identical final state.

## Found defects
### Q05-D1 (integrity) — duplicate AdventureAction/Observation ids
`src/slice/loop.ts:220` `makeSliceChoice` appends at `:239-240` without checking whether `input.actionId` / `input.observationId` already exist. Repro:
```ts
const once = makeSliceChoice(state, input);   // run active, not at encounter beat
const twice = makeSliceChoice(once, input);   // same input re-delivered
// twice.adventureActions has two records with id input.actionId; beat advanced twice
```
Expected: reject the repeat (or no-op). Suggested fix (product lane): throw/no-op when the action id already exists in `state.adventureActions`.

### Q05-D2 (UX, weaker) — combat round has no idempotency key
`src/slice/loop.ts:275` `playSliceCombatRound` takes no per-round key, so a double-delivered intent plays two rounds. No duplicate records result. The consequence id (`:303`) is only used on resolution. Suggested fix: a round/turn number or intent id checked against `activeCombat.state`.

Both are pinned with `it.fails` so the suite fails loudly once fixed (flip to `it`).
