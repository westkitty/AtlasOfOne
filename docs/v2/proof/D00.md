## Existing external ownership that must remain external

`App.tsx` already delegates important authority correctly:

- `src/game/**` — deterministic campaign/encounter/progression authority
- `src/cartographer/**` — provider/context/validation/model proposal boundary
- `src/world/**` — Worldwalker rendering, geography, sanctuary and audio primitives
- `src/persistence/**` — IndexedDB and transfer/migration boundary
- `src/voice/**` — access secret, MediaRecorder capture, local commands, STT state

The decomposition must reduce orchestration/UI concentration without pulling those authorities back into React components.

## Responsibility map

## Shared-state seams

The main collision risks are not visual components; they are these shared state clusters:

| Seam | State / callbacks | Consumers | Rule |
|---|---|---|---|
| Campaign authority | `state`, `dispatch` | nearly every surface | never pass raw setters that bypass engine events |
| Journal interaction | `prompt`, `answer`, `reply`, submit callbacks | journal, voice, provider | provider proposal cannot mutate campaign directly |
| Agency | PASS/PRIVATE/STOP/SERIOUS/HELP/sass | journal, encounters, future reflection/combat | keep one canonical behavior source |
| Async request identity | submission/request refs | provider, import, voice | preserve same-task/stale-response guards |
| Persistence | hydrated/load/save/import/delete | root, Me | no component-local shadow campaign |
| World interaction | talking/waystone/interior/travel/facing | Worldwalker | future D04 hook boundary |
| Presentation notices | queue/reveal/impact | global shell | presentation may observe progress, never grant it |
| Input mode | voice mode/state/capture | Journal shell | STT only; no TTS/output lifecycle |
| Encounter | derived active Boss/Door + submit/leave | encounter UI | deterministic engine owns outcome/reward |

## D01 authorized extraction

D01 should be deliberately boring.

### May move

- status/milestone presentation constants;
- Progress display;
- AgencyControls;
- AgencySheet;
- ActionBar;
- generic Menu/Sheet presentation if doing so does not expand the diff materially.

### Must remain in App during D01

- `dispatch` and all game-event construction;
- provider/context compilation and response application;
- persistence/hydration/import/delete;
- all V01 microphone/transcription lifecycle;
- Boss/Mystery submission logic;
- Worldwalker movement/travel orchestration;
- onboarding normalization/completion;
- Final Assessment/Snapshot migration logic.

### No new abstractions merely to match the target tree

Do not introduce a state manager, context provider, reducer wrapper, dependency, service layer, or generic “controller” hierarchy. Extract existing UI boundaries first.

## D02 boundary after D01

Create a Journal-facing shell that receives:

- prompt/reply text;
- editable answer;
- input-mode state;
- submit/change/mic callbacks;
- agency callbacks;
- accessibility labels/state.

It emits user intent only. It owns no provider call and no `GameEvent`.

## D03 boundary after D01

Create an Encounter presentation boundary that receives:

- already-derived encounter view state;
- deterministic objective/stage presentation;
- answer text;
- submit/pass/private/stop/leave callbacks.

It owns no availability, reward, XP, stage advancement, or completion logic.

## D04 boundary after D01

Extract Worldwalker orchestration hooks/components around:

- region/route selection;
- waystone/interior overlays;
- travel/facing/presentation state;
- callbacks into `WorldMap`.

Do not move deterministic campaign/world persistence into visual components.

## Regression radius

Every D01–D04 change must re-run at least:

- unit suite;
- production/PWA build;
- browser journey;
- concurrency;
- encounters;
- provider;
- PWA/offline;
- STT-only voice;
- onboarding/hydration;
- Worldwalker verb suite.

The full browser suite is the simplest acceptable gate while decomposition touches `App.tsx`.

## Stop conditions

Stop and return to contract review if an extraction requires:

- changing `GameEvent` vocabulary;
- changing persistence schema/migration;
- changing provider schemas/context;
- changing V01 STT semantics;
- adding a dependency;
- duplicating campaign state;
- weakening existing browser journeys;
- moving progression authority into a component.
