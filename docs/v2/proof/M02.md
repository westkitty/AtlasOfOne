## Migration behavior

- live `CampaignState.schemaVersion` is now `2`;
- fresh campaigns are created as schema v2 with all nine v2 collections empty;
- `CURRENT_SCHEMA_VERSION = 2`;
- schema-v1 input is parsed first by frozen `campaignStateSchemaV1`;
- the normalized v1 object is lifted to v2 with inert collection defaults;
- schema-v2 input validates idempotently;
- IndexedDB row payload is treated as `unknown` until the migration boundary validates it;
- Dexie database/store layout remains version 1 because the object-store topology did not change;
- historical `FinalAssessment` remains untouched in M02; M03 owns Snapshot migration.

## Strong preservation invariant

For each canonical M00 v1 fixture:

1. parse under frozen v1 authority;
2. migrate to v2;
3. remove only the nine v2 collections;
4. restore `schemaVersion: 1`;
5. the result must equal the normalized v1 object exactly.

This proves migration does not silently rewrite legacy turns, evidence, encounters, settings, world journey, assessment or other durable v1 state.
